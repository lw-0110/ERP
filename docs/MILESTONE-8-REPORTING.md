# Milestone 8 operational reporting

Reports use the active authenticated membership's organization; request bodies and query strings cannot select another organization. `from` and `to` are inclusive local calendar dates in the organization's current IANA timezone. The API converts local midnight boundaries to a half-open UTC interval using PostgreSQL `AT TIME ZONE`, including daylight-saving transitions. If dates are omitted, the organization-local current day is used. A query is limited to 366 calendar days. Invalid calendar dates and unknown filter fields are rejected.

## Metric definitions

- Booking report and status counts use `Booking.startDateTime` within the range. Service groups use the persistent service ID, BookingService quantity, and immutable duration/buffer snapshots. Current Service duration and price never revise reports. Staff assignment groups reflect the currently stored per-service assignments; the platform does not yet retain an assignment-change history. `todayBookings` on the dashboard always means bookings starting in today's organization-local day, even when another range is selected. `upcomingBookings` means currently `CONFIRMED` bookings starting between now and the selected range's end.
- Recorded payments use `PaymentRecord.paidAt`; payment-status distribution separately counts bookings starting in the range. An optional payment-status filter applies to both the recorded-payment rows (by their booking's stored status) and the distribution. Payment records never derive or alter `Booking.paymentStatus`. Amounts are grouped by ISO currency and never converted or added across currencies. Payment-method summaries are grouped by both currency and method.
- Recorded commissions use immutable `CommissionRecord.amountMinor` and `createdAt`, grouped by currency, staff ID, and service ID. Neither current Service data nor draft CommissionRule configuration is used to recalculate them. The staff self-report resolves the linked active StaffProfile server-side.
- Attendance uses organization-local `workDate`. Recorded attendance duration is the raw `clockOutAt - clockInAt` elapsed milliseconds for closed records only, with no break, rounding, overtime, or payroll interpretation. `currentlyClockedIn` is a present-state count independent of the selected historical range.
- Leave requests are included when their half-open leave interval overlaps the selected date range. Status, staff, and leave-type groups reflect current request fields. No cancellation or payroll rule is introduced.
- Staff operational detail shows current assignment counts for bookings starting in the range, completed-booking assignment count, recorded attendance duration, and leave status counts. Immutable recorded commission totals by currency appear only for a caller with `report.read.finance`. It does not calculate a performance score.

## API, permissions, and settings

`GET /reports/dashboard`, `/reports/bookings`, `/reports/attendance`, `/reports/leave`, and `/reports/staff/:id` require `report.read.operations`. `GET /reports/payments` and `/reports/commissions` require `report.read.finance`. The dashboard includes finance cards only when the authenticated membership also has finance-report permission. `GET /reports/commissions/my` requires `commission.read.own` and enforces staff ownership. Existing `report.export` plus the matching operations/finance read permission is required for `/exports/{bookings,payments,commissions,attendance,leave}.csv`.

The CSV endpoints reuse the corresponding report filters and tenant query, have stable headers, use UTF-8 with a BOM, escape CSV cells, and neutralize leading spreadsheet-formula characters. They omit customer contact information, secrets, notes, and commission explanations.

`GET/PATCH /settings/organization` reads or updates the existing organization name, IANA timezone, and default ISO currency, with backend validation and `organization.read`/`organization.settings.manage` permissions. No schema change or Milestone 8 migration is needed. Edits never rewrite historical booking, payment, or commission records. Booking-number prefix and customer cancellation/reschedule controls are not exposed because the existing booking workflow would not honor them without further approved policy and compatibility work.
